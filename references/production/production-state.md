# 项目状态、覆盖与返修

现有四类连续性台账仍是故事事实账。视觉信息附在同一台账的“视觉制作账”，可拆为被其索引的文件；仅保留一份当前权威状态。Skill目录存规则，项目根存源文/资产/预算/分镜/母稿，不把制作项目写进Skill或随意搜全盘猜“最新项目”。

## 最小可恢复记录

每个项目保留 project_id、项目根/source_ref/source_version、当前集场、用户决定和依据、有效风格正文、资产版本、稳定链登记、分段计划、母稿/适配版本、预算、显式物理状态、观看状态、覆盖账、检查证据和唯一下一目标。已在原项目中有完整状态时复用，不要求换成固定75字段，也不能只保留字段名丢掉原有事实。

覆盖账每行记录：集场/事件链或原文范围、formal_id、母稿版本、预算版本、起终态/观看变化、有效/失效、真实产物路径、检查范围。C01可在不同场使用；跨场引用采用EPxx-SCxx-Cxx避免碰撞。只登记实际交付，不用历史最大段号代替连续有效前缀；中间缺段应先补缺，保留仍有效后段并吸收其覆盖，不能再生成一次消费剧情。

继续制作前读当前原文、活跃台账、实际前驱文件、返修锁、相关阻断和下一未覆盖锚点。只有“继续”时沿原目标，不切换项目或重复初始化。前驱不存在/状态冲突时先据真实产物恢复，不能靠记忆假报读过。

新项目、已有完整状态、需要恢复是三条不同路径。状态完整且证据一致就继续，不因本规则更新而再次恢复/等待；确需恢复时列依据、版本、覆盖与缺项，完成恢复后保留用户原目标。用户明确授权本轮继续全部范围时可接着完成不依赖未决信息的工作。

## 返修传播

按“源文/规则/资产 → 动作/事件链 → 导演镜头 → 关键帧 → 母稿 → 适配稿/媒体”追踪真实依赖。

- 只改摄影表达而不改动作/末态/观看信息：保留原文覆盖，更新相关镜头与帧/母稿版本。
- 改位置、持物、伤损、声源、能力或揭示：复查使用这些状态的后续镜头和连接，不无差别作废全剧。
- 改段界：同步前末镜、后首镜、两个段状态、handoff、声音和预算；不能只改表格秒数。
- 改画风/换装：身份不重造；受影响外观版本失效，无关剧情和ID保留。
- 改资源/地形/代价：复查此后具体不能做什么；消耗品不得复活，慢镜资源不要拿成片秒差冒充世界耗时。

修订中的目标、原返回目标、依赖失效范围和待解决项保存在同一台账；修完复算并保存完整可用更新内容，用户不需要拼接零散差异。纯错字不影响时长/语义时只改该项。

## 重发、取消、阻断与返回

逐字复送：定位实际历史正文按字重送，不重新编译/复算/改生产状态；找不到就说明缺原文。普通重发：可重交同版完整内容，不移动覆盖游标。

补适配、缺图或平台能力未知时，为具体事项保存 request_id、目标、范围、版本与ACTIVE状态；只有依赖该条件的目标BLOCKED，原续作目标记return_to。用户补齐后关闭该项并回原目标，其他阻断保持；用户取消则CANCELLED，不能改成CHECKED，也不反复追加相同取消请求。覆盖不因补适配、重发、真实重试、观察反馈或额外生成任务再次增加。

工作完成后保存下一目标和真实状态，不增加Skill内部审批。用户只要局部产物时不能强制全部上游重做；用户要求全量制作时不能在第一段后以“继续”结束并宣称整场完成。

## 证据记录

检查记录包含 status、scope、evidence、version。PASS须定位实际核对材料和范围，仅“已读/已核对”不构成证据；未知/未执行用UNKNOWN/NOT_RUN，纯文字步骤输入可用NOT_APPLICABLE。机器验证、模型判断、用户观察分层报告，不用结构通过替代平台/媒体。

有文件能力时写入后重读验证再报告成功，失败保留上一有效状态；会话模式则提供足以恢复的完整活跃事实与引用，不假称已存盘。


历史5.0.0视觉包只有“本段正式时长”或把静帧/母稿放在独立文件时，迁移到文本契约1.1应据实际文件建立整场时长、分段表、帧与逐段母稿的检查视图，保留原文内容、版本和有效覆盖，不为过检改剧情。格式未被解析与故事缺陷分别报告；不得仅换版本标签或重做已完成项目。单场转译没有已定全剧时，不为消除S6警告编造总集数/付费墙，系列检查仅用于有全剧上下文的台账。
