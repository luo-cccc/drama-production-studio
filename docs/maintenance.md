# 维护说明

## 文件职责

`SKILL.md` 维护触发条件、任务范围、八种模式与必要路由；详细方法放在相应参考中。模板维护可填写结构和解析字段；示例展示实际交付，测试验证有意义的行为。文档和 `package-manifest.json` 记录名称、接口、目录及契约版本。

每条规则尽量只在一个参考中解释完整细节，入口与模板保留摘要和链接。剧本事实、导演表达、机器结构与实际媒体证据各有职责；修改表达规则时不改变用户指定事实。摄影词库与四套战斗JSON有实际复用价值，不能按体积直接判为冗余。

## 修改后的验证

```powershell
python -X utf8 -B scripts/verify_package.py --output 新检查记录.json
```

总检运行单元测试、单集及系列自测、标准/长档剧本、18秒视觉场景、1.2内容驱动分段示例、6秒忠实战斗场景与四套战斗JSON，记录每条命令、退出码和受测输入SHA-256。CLI证据文件只新建，不覆盖已有记录；包内verification-results.json是最近实际运行报告的副本，更新前的报告保存在包外归档中。输出放在新文件或包外归档目录；不要把历史技能副本或缓存复制到运行包。

需要定位失败时单独运行：

```powershell
python -X utf8 -B -m unittest discover -s tests -v
python -X utf8 -B scripts/check_episode.py --self-test
python -X utf8 -B scripts/check_series.py --self-test
```

改动命名、模块导入或目录时，还应在项目外目录使用 `python -I` 调用绝对脚本路径，并实际导出战斗包。不得通过临时加入原工作区到 `sys.path` 掩盖缺失依赖。机器检查以包内文件为准，运行不依赖两个来源目录、原安装路径或网络。

Skill Creator的 `quick_validate.py` 可检查入口格式和命名；该工具属于宿主开发环境，不是本包运行依赖。真实用户模拟与机械回归分开记录，方法见[评测规程](../references/review/evaluation-method.md)。旧模拟已看过后属于回归素材，不能再次称为新保留题或盲评。

## 命名与兼容

包标识、入口 `name` 和包清单均为 `drama-production-studio`；工作区检出目录允许带环境后缀，不参与包身份判断。内部Python文件使用下划线，文档、模板与示例使用语义化小写连字符。`SKILL.md`、`README.md`、`CHANGELOG.md`、`LICENSE` 为保留文件名。

现有自然语言模式、命令别名、E/V/S编号、JSON1.1/1.2、视觉文本契约1.2（1.1兼容）及导出文件名保持其接口含义。改名映射在[迁移说明](migration.md)及[机器映射](name-map.json)。文件移位需同步Markdown相对链接、代码中的路径、邻接模块加载、测试和来源清单目标。

## 证据与归档

运行包只留当前说明、当前验证摘要和有用示例。旧失败日志、源码快照、重复模拟与原始压缩包归入包外恢复档案；原始来源指纹和通知保留在[来源清单](source-manifest.json)及[上游通知](upstream-notices.md)。保留许可和归属，不将改名解释为重新授权。

报告分别标注结构验证、语义复核、预算估算、独立模拟、实际输入、媒体与外部审核。Windows缺少符号链接权限时如实记录跳过项；普通导出与拒绝覆盖仍应实际验证。程序化检查、模型判断和真人反馈是不同证据类型，没有通用的高低排序。
