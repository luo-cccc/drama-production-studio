# 来源与能力归属

短剧创制工作室由原短剧编剧包整合通用分镜提示词和仙侠斗法设计后整理而来。两个来源目录均为用户提供的本地输入，运行包已包含所需内容；来源目录不是运行依赖。

## 能力位置

| 来源能力 | 当前实现 | 处理方式 |
|---|---|---|
| 原短剧编剧体系 | `references/story/`、`references/writing/`、`references/review/`、剧本和台账模板、E/S检查 | 保留情绪契约、信息阶梯、人物、单元回合、正文、连写与修订方法；删旧营销和无法复核的数据。 |
| `script-to-storyboard-prompts-main` | `references/production/`、视觉包模板、V检查 | 适配人物母图/四视图、场景道具、观看任务、事件链、预算、镜头、静帧、逐段母稿、模型适配和状态返修。 |
| 来源包摄影资料 | [摄影词库](../references/production/camera-language.md) | 收录参考正文并调整本地标题/引用；按需查阅。 |
| `xianxia-fight-director-main` 的设计方法 | `references/fight/` 与资产/时长参考 | 适配九类机制、攻防回应、代价、地形、信息差、呼吸、光源、风险保底和返修方法。 |
| 来源包战斗代码、契约与测试 | [内部工具](../scripts/fight_contract.py)、[数据契约](../references/fight/fight-data-contract.md)、[回归测试](../tests/test_fight_contract.py) | 本地适配，保留结构、数值校验、同源六项导出与拒绝覆盖行为。 |
| 来源包四份战斗JSON | `examples/fight/` | 只改文件名，JSON字节及来源SHA-256保持不变。 |

## 文件指纹与声明

[来源清单](source-manifest.json)逐项记录来源包名、包内文件、原始SHA-256、当前目标文件及吸收方式。来源路径表示归属，不要求用户复现原电脑目录。重命名后的目标均指向当前包，原始指纹不因目标改名而改写。

原项目的MIT文本保留在 [LICENSE](../LICENSE)。来源包中的许可与参考关系见[上游原始通知副本](upstream-notices.md)；其中“本包”等称谓指该通知原所属包，不能读作本次重新授权。根MIT不被推定覆盖未声明许可的第三方正文、代码或样例。改名不改作者归属与来源事实。

原编剧参考内标明的JYY v3.8、jyy-script-creation-v2等名称属于历史方法归属，源包未作为本轮新增运行资源。历史榜单和法规摘要没有随整理变成现时结论；实际外部核验需另存可复现材料。

## 整合方式

6.1.0新增的[内容驱动分段](../references/production/segment-planning.md)为本包在既有流程上的原创整理，不来自上述来源包，也不改变其归属与许可。

所有能力由根SKILL路由，不引入来源包的独立入口，不复制第二份故事事实账。用户的一次完整交付、分阶段选择、原文忠实转译和局部修订范围由同一工作流处理。普通用户使用自然语言；战斗JSON只是可选存档与导出工具。
