# 技能评测与真实使用验证

本规程用于维护本技能。包的结构正确、生成的内容成立、真实媒体可用属于不同结论，应分别提供证据。没有可用的独立评审资源时如实记录，不把自查称为盲评。

## 一、选择与冻结用例

按改动范围选固定回归、对抗输入及必要的新任务。冻结真实请求、源文、用户条件、交付范围与受测版本；改动前后使用同一输入进行可比检查。用过的样本可继续回归，但不再是独立保留题。

行为验证重点覆盖：只要剧本、定稿短场、全场多段、原创斗法、局部返修、续作恢复、取消和逐字重发。选择本次改动实际影响的路径，不为每次文档调整重复跑完整创作。

## 二、程序化检查

运行 `scripts/verify_package.py` 保存命令、退出码、输入SHA-256和跳过项。E/V/S、存档、导出和链接检查只证明其实际覆盖范围。失败保留真实记录，修复后以新文件重跑；不要覆盖旧证据或只报告通过次数。

## 三、实际任务与独立评审

复杂流程改动可在授权范围内让独立执行者读取技能和最少原始输入，在隔离目录完成真实用户请求。不给预设答案和待修缺陷；评审实际文件而不是仅采信执行者口头结论。检查源文、台词、事件、揭示、覆盖、资产、时轴、显式状态和每段母稿是否满足请求。

比较新旧稿时，可去标识、打乱顺序交独立评审者，用[修订问题卡](revision-protocol.md)记录具体因果与内容问题。保留题一旦看过即转为回归素材；修复后再测同题属于闭环复测，不称新独立验证。

## 四、证据记录

| 类型 | 可支持的结论 | 不能代替的结论 |
|---|---|---|
| 程序运行 | 字段、状态、时间、命令、拒绝覆盖等受测行为 | 故事情理、真实模型输入、媒体效果 |
| 模型或人工语义复核 | 原文保真、因果、人物、揭示与交付完整性 | 实际片长、平台审核、观众反馈 |
| 试读或走读 | 特定语言、表演、版本的测量时长 | 未试读版本或不同表演的成片时长 |
| 媒体观察 | 实际看见/听见素材的可见问题 | 未生成、未观看的后续结果 |
| 用户反馈 | 该用户与样本中的实际体验 | 整个平台热度或成功率 |

证据类型之间不作通用高低排序。记录scope、输入/产物版本、材料路径、实际结论和未核项；未知写UNKNOWN，未执行写NOT_RUN。禁止用总分、星级或虚构百分比预测爆款。

## 五、报告与停止条件

报告写清修复了什么、引入了什么代价、回归是否通过、实际用户路径还有哪些未验证。问题卡采用[修订规程](revision-protocol.md)，保护性例外见[审阅例外](review-exceptions.md)。检查通过且没有新改动或具体未决风险后完成交付，不反复扩张测试范围。

本文件继承原技能的对照评测、保留题与证据分层方法；其中JYY v3.8是历史方法参考名，不是运行依赖或本次实测结论。当前结果见[验证记录](../../docs/verification.md)。
